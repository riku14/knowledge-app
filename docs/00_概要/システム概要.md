# システム概要

## 1. プロジェクト概要

### 1.1 プロジェクト名

ナレッジ共有アプリケーション

### 1.2 目的

企業やチーム内でのナレッジ共有を促進し、情報の属人化を防ぐ。組織全体の知識を一元管理し、効率的な情報共有を実現する。

### 1.3 対象ユーザー

- 企業の従業員（全社員）
- チームメンバー
- 管理者・チームリーダー

## 2. システムアーキテクチャ

### 2.1 現状（デモ版）

- **種別**: シングルページアプリケーション（SPA）
- **フロントエンド**: React 18（CDN版）
- **スタイリング**: Tailwind CSS
- **データ管理**: クライアントサイド（モックデータ）

### 2.2 将来の拡張

- **バックエンド**: Java
- **データベース**: PostgreSQL
- **認証**: JWT（JSON Web Token）
- **API**: RESTful API

## 3. 主要機能

### 3.1 記事管理

- 記事の作成・編集・削除
- Markdown形式の記述
- カテゴリ・タグによる分類
- 公開範囲の設定（全体公開/チーム限定）
- 承認フロー（全体公開時）

### 3.2 コメント機能

- 記事へのコメント投稿
- コメントの削除

### 3.3 お気に入り機能

- 記事のお気に入り登録・解除
- お気に入り一覧表示

### 3.4 検索機能

- キーワード検索（タイトル/本文/タグ/投稿者）
- 詳細フィルター（カテゴリ/公開範囲/日付範囲）

### 3.5 管理機能

- **タグ管理**: タグの作成・編集・削除（管理者・リーダー）
- **チーム管理**: チームの作成・編集・閉鎖（管理者）
- **ユーザー管理**: ユーザーの作成・編集・削除（管理者）
- **承認機能**: 記事の承認・差し戻し（管理者・リーダー）

## 7. データフロー

### 7.1 記事作成フロー

```
1. ユーザーが記事作成画面で入力
2. フォームバリデーション
3. バックエンドAPIに送信
4. データベースに保存
5. レスポンスを受け取り、画面更新
```

### 7.2 記事承認フロー

```
1. ユーザーが全体公開記事を投稿
2. status='pending'で保存
3. 管理者・リーダーが承認待ち一覧を確認
4. 承認 → status='published'
5. 差し戻し → status='rejected'、理由付き
```

## 8. セキュリティ

### 8.1 認証・認可

- JWT（JSON Web Token）による認証
- ロールベースアクセス制御（RBAC）
- パスワードはハッシュ化して保存

### 8.2 セキュリティ対策

- XSS対策: 入力値のサニタイゼーション
- CSRF対策: CSRFトークン、SameSite Cookie
- SQLインジェクション対策: プリペアドステートメント

## 9. パフォーマンス目標

- **ページ読み込み時間**: 3秒以内
- **APIレスポンス時間**: 1秒以内
- **検索実行時間**: 2秒以内
