# セキュリティ設計書

## 1. 概要

ナレッジ共有アプリケーションのセキュリティ設計書です。セキュリティ対策とリスク管理の指針を記載します。

## 2. セキュリティ要件

### 2.1 認証・認可

- **認証方式**: JWT（JSON Web Token）
- **パスワード**: bcrypt等でハッシュ化（salt + rounds）
- **セッション管理**: トークンの有効期限管理
- **権限管理**: ロールベースアクセス制御（RBAC）

### 2.2 データ保護

- **通信暗号化**: HTTPS必須
- **データベース**: パスワード等の機密情報はハッシュ化
- **バックアップ**: 暗号化して保存

## 3. 主要なセキュリティ対策

### 3.1 XSS（クロスサイトスクリプティング）対策

#### 3.1.1 入力値のサニタイゼーション

- ユーザー入力はすべてエスケープ処理
- Markdownコンテンツも適切にサニタイズ
- Reactの`dangerouslySetInnerHTML`使用時は厳重に検証

#### 3.1.2 Content Security Policy（CSP）

```
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
```

### 3.2 CSRF（クロスサイトリクエストフォージェリ）対策

- **CSRFトークン**: フォーム送信時にトークンを検証
- **SameSite Cookie**: Cookie属性にSameSite=Laxを設定
- **Originチェック**: リクエストのOrigin/Refererを検証

### 3.3 SQLインジェクション対策

- **プリペアドステートメント**: すべてのSQLクエリで使用
- **パラメータ化クエリ**: ユーザー入力を直接SQLに埋め込まない

### 3.4 認証・認可の実装

#### 3.4.1 JWTトークン

```javascript
// トークン生成
const token = jwt.sign(
  { userId, role, email },
  process.env.JWT_SECRET,
  { expiresIn: '24h' }
);

// トークン検証
const decoded = jwt.verify(token, process.env.JWT_SECRET);
```

#### 3.4.2 パスワードハッシュ化

```javascript
// bcryptを使用
const saltRounds = 10;
const hashedPassword = await bcrypt.hash(password, saltRounds);

// 検証
const isValid = await bcrypt.compare(password, hashedPassword);
```

### 3.5 入力バリデーション

- **フロントエンド**: ユーザビリティ向上のため実装
- **バックエンド**: 必ず実装（フロントエンドを信用しない）
- **サーバーサイドバリデーション**: すべての入力に対して実施

### 3.6 ファイルアップロード対策（将来実装時）

- **ファイルタイプ検証**: MIMEタイプと拡張子の両方で検証
- **ファイルサイズ制限**: 最大サイズを設定
- **ウイルススキャン**: アップロードファイルをスキャン
- **安全な保存先**: Webアクセス可能なディレクトリ外に保存

## 4. アクセス制御

### 4.1 ロールベースアクセス制御（RBAC）

| ロール | 権限 |
|--------|------|
| admin | 全機能アクセス可能 |
| leader | タグ管理、承認機能、チーム記事管理 |
| member | 記事閲覧・作成、お気に入り、コメント |

### 4.2 リソースレベル認可

- **記事編集**: 記事の作者のみ編集可能
- **記事削除**: 記事の作者のみ削除可能
- **コメント削除**: コメント投稿者または記事作者のみ削除可能

## 5. ロギング・監視

### 5.1 ログ記録

- **認証ログ**: ログイン成功/失敗
- **アクセスログ**: APIリクエスト、エラー
- **操作ログ**: 記事作成・更新・削除、承認等

### 5.2 監視項目

- 不正アクセス試行
- 大量リクエスト
- エラー発生率
- レスポンス時間

## 6. セキュリティインシデント対応

### 6.1 対応フロー

1. **検知**: ログ分析、アラート検知
2. **調査**: 原因特定、影響範囲確認
3. **対応**: 緊急措置、修正実装
4. **報告**: ステークホルダーへの報告
5. **再発防止**: 対策の見直し

## 7. プライバシー保護

### 7.1 個人情報保護

- **データ最小化**: 必要最小限の情報のみ収集
- **アクセス制限**: 個人情報へのアクセスをログ記録
- **データ削除**: 退会時のデータ削除機能

### 7.2 GDPR対応（将来）

- ユーザーのデータ権利（アクセス、削除、移植）
- 同意管理
- データポータビリティ
